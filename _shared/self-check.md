# 发布前自检

发布仓没有"预览环境"这一层——**发布即承诺**。以下每条必须在发布前成立，逐条留证。

> 第一、二、三、五节的可机检部分由 `python3 _shared/tools/validate.py` 检查；其余逐条人工确认并留证。

## 一、自包含

客户 AI 在零上下文下工作：它没有我们的 Workspace、没有产品仓、没有内部文档。

- [ ] 产品目录（或快照目录）内所有相对链接可解析。
- [ ] **零外链指向本仓之外**（产品官方文档等外部资源除外，且须注明"外部资源"）。
- [ ] `SKILL.md` 能独立说明"这个产品是什么、什么时候该用它"，不依赖 `references/` 之外的材料。
- [ ] `references/` 里的相对链接只指向同一目录内。

## 二、一致性

- [ ] 工具合同里的工具名，与 Skill 正文里引用的工具名**逐字一致**。
- [ ] 错误码、对象名、字段名与产品实际行为一致。
- [ ] 观测时点与产品版本写在文档头。
- [ ] `MANIFEST.json` 的 `assets` 条目与目录实况逐个对得上（不多不少）。
- [ ] `MANIFEST.json` 的 `sourceCommit` 回指产品仓中的一个确定提交。

## 三、安全

- [ ] 无凭据、无令牌、无私钥、无 `user:pass@` 形式字面量。
- [ ] 无内部地址、内网主机名、内部工单号、内部人员姓名。
- [ ] 无测试环境信息、无内部测试数据。
- [ ] 隐藏／截断标记保持原样，不出现"如何还原隐藏值"的指引。
- [ ] 面向公开仓，**内容按"客户会截图转发"的标准审过一遍**。

## 四、可用性

- [ ] 每个交付形态都**真实验证过**：Skill 在至少一个宿主里跑通；MCP 每个工具实际调用通过；提示词在无技能环境下给出过正确结果。
- [ ] 未验证的形态**已删除**，不留空壳。
- [ ] `README.md` 的一句话安装提示词**已填好实际值**，可直接复制使用。
- [ ] 版本限量写清（如"本版本只读"），且与工具合同的注解一致。

## 五、仓级

- [ ] 内容文件**全部由产品仓生成**（`publish.py`），无手工编辑。
- [ ] 本次发布**不改动** `releases/` 下任何快照的内容文件。
- [ ] 存快照时，被取代的快照 `status` 已改为 `superseded`；被撤回的改为 `yanked` 并在 `INDEX.md` 顶部公告。
- [ ] `INDEX.md` 各行与 `MANIFEST.json` 一致，各列填全。
- [ ] 发布仓提交为**路径限定提交**，提交前已核对索引。

## 六、发现了问题怎么办

- 发布仓里发现与产品实际行为不符：**提 Issue，不改圆**。改圆会让下一个客户按错误材料操作。
- 当前版本发现缺陷：修正产品仓后重新发布。
- 快照发现缺陷：改 `status` 为 `yanked` ＋ `INDEX.md` 公告并说明替代版本。**不删快照、不改快照内容。**
