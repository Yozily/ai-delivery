# 连接 PgTool

PgTool 的 AI 资产是一个工具包，`skills/` 下每个目录是一个技能：

| 技能 | 作用 | 是否调用接口 |
|---|---|---|
| `pgtool` | 基础与导航：概念、客户端与云后台的分工、通用规则 | 否 |
| `pgtool-client` | 客户端（桌面产测端）只读查询与诊断 | 是，本机 HTTP，只用 GET |

云后台技能暂未提供。

## 安装

把 `skills/` 下的全部技能一起安装。`pgtool` 是基础技能，其他技能依赖它的概念与规则；只装 `pgtool-client` 也能工作，但对象区别和通用规则会缺失。

## 服务地址

PgTool 桌面端启动后，固定在 `http://127.0.0.1:10532` 提供服务。技能默认使用这个地址，用户不需要提供。

只有管理员通过环境变量 `PGTOOL_APIHOST_PORT` 改过端口时，地址才会不同；这时由管理员告知新端口。

## 前提（pgtool-client）

1. **AI 运行在装有 PgTool 的同一台电脑上。** `127.0.0.1` 指本机；在云端或另一台电脑上运行的 AI 访问不到。
2. **PgTool 桌面端已经启动。**
3. **AI 有一个能发 GET 请求的工具**，按宿主选择：

| 宿主 | 做法 |
| --- | --- |
| 自带网页抓取工具的宿主 | 直接使用。部分宿主禁止访问本机地址，此时换下一种 |
| 支持 MCP 的宿主 | 添加通用抓取类 MCP 服务器，例如开源的 `mcp-server-fetch`（外部资源，stdio 方式，命令 `uvx mcp-server-fetch`） |
| 能执行命令的宿主 | 用 `curl` 发 GET 请求；建议在权限设置中只放行 GET |

## 自检

让 AI 读取 `http://127.0.0.1:10532/api/shell/readiness`，返回中 `status` 为 `ready` 即连接正常。

## 使用边界

- 本版本只读，请在宿主中保持「调用工具前确认」。
- PgTool 接口目前没有访问认证，不要把这个端口转发或暴露到其他网络。
