# PgTool 产品概览

## 1. 它是什么

PgTool 是产品测试工具链。它把四件事连成一条业务线：

1. 准备测试内容：定义测试流程、变量、设备参数、测试标准，并发布部署。
2. 现场执行：在产线启动测试会话，工位触发测试，实时显示结果并处理交互。
3. 留存记录：每次工位测试的终态形成正式测试记录，可检索、追溯。
4. 同步与统计：记录同步到云端，做订单、合格率等集中统计。

产品分两个交付端：

- 桌面产测端：本机运行，含 Web 工作区。流程编辑、会话执行、本地记录、设备接入都在这里。
- 云平台：集中接收记录、做统计、管理产线与产品信息。

## 2. 谁在用

| 角色 | 目标 |
|---|---|
| 测试方案维护人员 | 管理项目、编辑调试流程、发布部署 |
| 现场操作人员 | 启动会话、工位操作、查看反馈 |
| 生产与质量人员 | 记录查询、统计 |

你协助的主要是测试员和生产工程师：看问题、调试测试流程。你不是开发人员，不需要也不应当依赖源码。

## 3. 业务主线

准备测试内容 → 选择并启动会话 → 工位触发与执行 → 结果记录 → 同步上云与统计。

要点：

- 启动会话不等于创建工位的一次测试运行。停止会话、终止工位、重试是三种不同操作。
- 记录以工位运行终态为粒度，没有工位运行的空会话不产生记录。
- 烧录、标贴是候选领域，本包不涉及。

## 4. 九个业务模块

| 模块 | 管什么 | 典型问题 |
|---|---|---|
| 01 测试会话管理 | 启动停止、工位触发与终止、重试重跑 | 为什么启动不了；为什么停不下来 |
| 02 测试执行呈现 | 工位与测试项、结果汇总、交互弹窗、诊断 | 现在测到哪一步；为什么弹窗卡住 |
| 03 测试内容准备 | 项目、流程、测试标准、变量资源、调试、发布部署、本地绑定 | 流程怎么写；为什么发布后不生效 |
| 04 测试结果与记录 | 记录留存、检索、分析、备份恢复 | 某次测试的结果是什么 |
| 05 生产统计与质量 | 订单统计、测试统计、统计口径、云端统计 | 合格率怎么算 |
| 06 记录同步与上云 | 同步队列、失败重试、离线记录包 | 记录为什么没到云端 |
| 07 设备接入与仪器集成 | 设备状态、连接配置 | 设备为什么连不上 |
| 08 产线身份与产品定义 | 产线身份、产品定义、设备 ID 分配 | 产品与产线怎么关联 |
| 09 应用壳与系统支撑 | 程序选择、主题语言、系统状态、宿主设置 | 应用是否可用 |

共 38 项功能，按模块归属。

## 5. 关键对象与生命周期

```text
作者态项目 → 校验/编译 → 调试 → 不可变 Release → Deployment → 本地绑定 → 测试会话
  → 运行终态事实 → 正式测试记录 → 同步 → 统计与质量
```

必须区分，它们不是同一个东西：

```text
流程定义 ≠ Release ≠ Deployment ≠ 运行会话 ≠ 测试记录 ≠ 统计结果
```

- 项目是正在编辑的版本；Release 是发布后不可变的版本；Deployment 是 Release 在某台设备上的部署。
- 产线身份、产品定义、设备连接是启动测试的前提。
- 「版本」有三种含义：作者态的当前版本、已发布的版本、实际生效的版本。引用时说清是哪一种。

## 6. 使用边界

- 本版本只读：你可以读取信息、给出建议与检查结果；修改内容、重试、启动或停止测试都由用户在 PgTool 界面操作。
- 服务端会强制互锁、占用、版本冲突和权限校验。不要尝试绕过，也不要把这些拒绝当成故障重试。
- 一次接口返回 200，不代表设备在线或测试可运行。以部署状态和运行快照为准。
- 数据可能含敏感字段。不要把凭据、令牌写进回复或日志。
