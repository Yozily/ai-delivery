# 案例

每个案例给出：问题、做法、当前程度、注意事项。程度分「可做」「部分可做」「暂不可做」。接口见 api.md。

## 案例 1：了解当前环境

- 问题：「这台电脑现在在做哪个工单？」
- 做法：读服务就绪、产线身份、生产上下文。生产上下文中的字段：`orderNumber`（工单号）、`productModel`（型号）、`orderQuantity`（数量）、`operatorName`（操作员）、`orderValid`（工单是否有效）。
- 同时看 `productDefinition`、`productionConfig`：字段全为空串表示尚未绑定产品定义或生产配置，可能影响能否测试，应提示用户。
- `cloudSync.lastError` 是当前与云端连接的最近一次结果，可顺带说明。
- 程度：可做。
- 注意：问「能不能测」时，转到案例 7。

## 案例 2：看一个测试流程里有什么

- 问题：「某项目的主流程有哪些步骤？」
- 做法：
  1. 定位项目 ID。项目列表很大，常常读不全；请用户给出项目名称，在可见部分查找。
  2. 读该项目的工作流列表，找到入口工作流（`isEntry: true`）。
  3. 先用 `depth=3` 读大纲看规模；如果最深一层仍有 `childCount` 大于 0 而未展开，直接改用 `depth=10` 一次读全。
  4. 入口工作流常是多层骨架（并行、循环、等待触发、派发），真正的测试步骤在被派发的工作流里（例如「测试调度」）。看到派发节点时，在工作流列表找到目标工作流，同样读大纲。
  5. 步骤顺序按大纲中 `children` 的先后。
  6. `catch`（异常收尾）、`finally`（收尾）、`return` 不是测试步骤，单独列为收尾。
  7. 看到 `loop` 里套着等待触发，表示每测一台都重新等待触发。
- 用户能直接给出项目 ID 时，跳过第 1 步。
- 程度：可做。
- 注意：项目的 `description` 是作者填写的说明，可能过期；以大纲为准，发现不一致时告诉用户。

## 案例 3：判断某个流程是否已部署最新内容

- 问题：「这个项目在本机部署的是最新的吗？」
- 做法：
  1. 项目内容时间：工作流列表返回的 `revision`，冒号后的时间是内容最后修改时间。不要用项目的 `metadata.updatedAt`，它可能滞后。
  2. 部署时间：部署列表按部署 ID 排序，与时间无关；如果只能看到一部分，可见部分在时间上是随机的。传 `projectId`、`limit` 不会报错，但不生效，仍返回全量。
  3. 更可靠的线索：最近一条测试记录的 `sessionId` 形如 `production-test:{deploymentId}:run:{runId}`，其中的部署是最近实际运行过的部署。用部署 ID 读单个部署得到 `deployedAt`。
  4. 某个部署下存在活跃执行（如 `runtimeStatus: Waiting`），是「本机正在用这条部署」的最强证据。
  5. `status: active` 只说明部署记录有效，不等于本机正在使用。
  6. 部署的 `definitionHash` 与项目 `revision` 是两套不同的值，不能直接比较，只能比时间。
- 证据强弱：活跃执行 > 最近测试记录 > 部署列表（部署列表不能用来判断最新）。
- 结论口径：可以说「最近运行的部署晚于（或早于）内容修改时间」；不能断言「本机正在用的就是最新」，并说明原因。
- 程度：部分可做。

## 案例 4：一次测试失败了，为什么

- 问题：「某条线当前的测试为什么失败？」
- 依次尝试以下路径，哪条通用哪条。

路径 A：从测试记录出发（最常用）

1. 记录检索 `Page=1&PageSize=1` 取最近一条记录；需要特定工单时加 `OrderNumber`。
2. 记录很大（常超过 200KB）。测试项在前，`isSuccess`、`message`、`errorItemName`、`createTime` 等结论字段在末尾，返回被截断时往往读不到。读不到时如实说明，请用户在界面核对记录结论。
3. 测试项看 `runState`、`verdict`、`runtimeStatus`：
   - `runState: Cancelled`、`verdict: None`、`runtimeStatus: Failed` 表示被取消，组按「必需项未通过」判为失败，不是测量超差。
   - 多个测试组在同一时刻被取消，通常是整次运行被中止（推测），具体原因看取消原因字段或请用户在界面确认。
   - 测量项有 `passed` 等结果时，可说明哪些步骤已通过。
4. 记录中含 `DeploymentId`、`DeploymentDescriptorHash`、`WorkflowExecutionId`，可用于路径 B。
5. 单条记录很大，可能读不全；说明你看到了哪些部分。

路径 B：从部署与执行出发

1. 用部署 ID 与部署描述哈希取活跃执行，没有则取最近执行，得到 `executionId` 与 `generation`。
2. 读工作台：`presentation.rootStatus`、`state.summary`、`executionFailures`、`consistencyIssues`、`state.deviceSummary`；需要细节时读调试快照。

路径 C：死信事件

- `sessionId` 留空取最近事件，可看到落库失败的节点、执行 ID 与原因。服务重启后可能为空。

诊断通道本身的问题：

- 工作台或调试快照返回 `session-binding-not-found`：该执行的生产配置会话绑定不存在。
- 执行状态返回 `ownership_scope_denied`：当前身份无权读取该执行。
- 活跃或最近执行返回 `not-found`：该部署当前没有执行，不是故障。
- 这些结果不是互锁、占用这类正常保护，而是诊断数据拿不到。把它们作为线索报告给用户，并说明需要管理员或界面协助。

- 按诊断输出格式回答。错误码因情况而异，不要套用固定答案。
- 程度：部分可做。通常能定位失败的运行与失败组，取消原因与子项明细不一定拿得到。

## 案例 5：测试记录没到云端

- 问题：「记录怎么没同步上去？」
- 做法：
  1. 读同步汇总，得到各同步状态的数量。汇总不含错误码分组。
  2. 同步列表按记录时间升序排列，第 1 页是最早的，最新的在最后一页。用汇总的 `total` 算出最后一页（例如 `total` 120、`pageSize` 50，最后一页是第 3 页）。按 `lastErrorCode` 和时间归纳；同一错误码可能对应不同原因，看 `lastErrorReason`。
  3. `cloudSync.lastError` 是当前连接探测结果，可能与队列里最后一条失败原因不同，两者分开说。
  4. 同步条目的 `recordId` 与测试记录的 `uid` 对应。某条记录未出现在同步列表中时，接口没有说明原因，如实告诉用户，不要断言丢失。
  5. 同步列表的 `recordCreatedAt` 没有时区标记（本地时间），与带 `+00:00` 的 UTC 时间比较时要注意。
- 错误码与处理方：

| 错误码 | 含义 | 找谁 |
|---|---|---|
| `remote_unavailable` | 云端不可达（连接被拒、网关 502） | 运维 |
| `identity_provider_unavailable` | 身份服务发不出机器令牌 | 身份服务管理员 |
| `identity_provider_rejected` | 身份服务拒绝 | 身份服务管理员 |
| `identity_provider_rate_limited` | 身份服务限流，本身是临时问题 | 等待后重试 |
| `invalid_client`、`machine_credential_unavailable` | 机器凭据失效或缺失 | 平台管理员 |
| `forbidden` | 凭据没有该操作权限 | 平台管理员 |

- `PermanentFailure` 表示自动重试已用完，不会再自动传；问题修好后仍需用户在界面手动重试。原因不同的记录建议分批重试。
- 记录的 `productModel` 取自当时的工单，不是项目。按型号查记录为 0，不代表该项目没有记录。
- 程度：可做；精确的按错误码计数需翻完所有页。

## 案例 6：修改流程中的某个步骤

- 问题：「把等待时间从 5 秒改成 10 秒。」
- 做法：用大纲和节点定位该步骤，向用户确认；给出修改建议（节点、字段、原值、新值）；说明修改后需发布并部署才会在产线生效。
- 程度：部分可做。只给建议，由用户在编辑器中修改。

## 案例 7：能不能测，以及启动测试

- 你不能启动、停止、终止或重试测试；即使条件全部满足，也要请用户在界面操作。
- 前提检查清单：

| 检查项 | 怎么查 | 不满足时 |
|---|---|---|
| 服务就绪 | 就绪接口 `status: ready` | 阻塞 |
| 产线身份 | 身份状态 `active` | 阻塞 |
| 工单有效 | 生产上下文 `orderValid` | 阻塞 |
| 工单型号与要测的项目相符 | 没有字段关联型号与项目，项目名称只是代号 | 不能判定，向用户提问确认，不要直接判阻塞 |
| 产品定义与生产配置已绑定 | 生产上下文中两者字段非空 | 很可能阻塞，标为推测 |
| 项目有可用部署 | 单个部署 `status: active`、`releaseAvailability: verified` | 阻塞 |
| 没有同项目执行正在运行 | 对已知部署逐个查活跃执行 | 只能对查过的部署下结论，其余写「未知」 |
| 上一次运行结果 | 最近一条测试记录 | 失败时提醒用户先处理 |
| 设备在线 | 当前无接口；单个部署的 `appliedLocalBindings.devicePortMappings` 列出绑定的设备端口，可提示用户逐一检查 | 写「未知」，请用户在界面确认 |
| 云端可达 | `cloudSync.lastError` | 不阻塞启动，但记录传不上去 |

- 型号目录接口当前返回空，不能用来核对型号。
- 回答「能不能测」时，结论只用三种之一：「满足已查条件，可以在界面启动」「有阻塞项，先处理」「有未知项，请在界面确认」，并附上清单。
- 程度：前提检查部分可做；启动不开放。
