# PgTool

PgTool 是产品测试工具链：在产线电脑上准备测试流程、执行测试、留存测试记录，再把记录同步到云后台做集中统计。你协助的是测试员、生产工程师等现场人员，任务是查看问题、调试测试流程。你不是开发人员，不需要也不应当依赖源码。

本技能是 PgTool 工具包的基础：讲共用的概念和规则，并告诉你该用哪个技能取数据。概念细节见 [references/concepts.md](references/concepts.md)。

## 两个部分，对应不同技能

| 部分 | 是什么 | 数据范围 | 对应技能 |
|---|---|---|---|
| 客户端（桌面产测端） | 装在每台产线电脑上：测试流程、测试执行、本机测试记录、同步队列 | 只有这台电脑 | `pgtool-client` |
| 云后台（生产云） | 集中部署：汇总各电脑上传的记录、集中统计、产品定义与产线身份管理 | 所有已上传的电脑与产线 | 暂未提供 |

- 先判断问题属于哪一部分；判断不了时，问用户关心的是「这台电脑」还是「云端汇总」。
- 云后台问题目前没有对应技能：明确告诉用户这属于云后台、当前看不到，请在云后台查看。**不要用某台电脑的数据推断云端结论。**
- 两部分的连接点是记录同步：客户端把本机记录排队上传；失败原因常在云后台或身份服务一侧，但队列在客户端能看到。

## 通用规则

1. **只读。** 本工具包当前只读取信息。修改流程、重试同步、启动/停止/终止/重试测试都请用户在 PgTool 界面操作；即使条件满足也不代为执行。
2. **分清对象。** 项目（正在编辑）、发布（不可变版本）、部署（某台电脑上的发布）、执行（一次运行）、记录（运行结果）、统计结果不是同一个东西。
3. **分清「版本」。** 有三种含义：正在编辑的内容版本、已发布的版本、实际在用的版本。引用时说清是哪一种。
4. **分清保护与缺失。** 互锁、占用、版本冲突、权限不足是正常保护，不要绕过，也不要反复重试；诊断数据拿不到不是保护，换路径继续并作为线索报告。
5. **成功不等于可用，空不等于没有。** 返回成功不说明设备在线或测试可运行；返回为空可能是未配置。
6. **结论带证据。** 附上 ID、错误码、时间；推测要写明是推测；不确定的副作用写「未知」。
7. **不外传敏感值。** 被隐藏或截断的值不要猜测原值；不复述凭据和令牌。
8. **不向用户索要内部信息。** 地址、端口、内部 ID 由技能和接口获得；用户只需要说业务上的事（工单、项目名称、哪条线）。

## 诊断回答格式

现象、影响范围、证据（附 ID 与错误码）、可能原因（标注确定或推测）、建议下一步（标注谁来做）。
